# SPOTCHU — 전체 유저 플로우 (인수 조건 통합본)

> 각 `docs/features/*/spec.md`에 이미 정의된 인수 조건(Given/When/Then)을 전부 한곳에 모은 문서다. 새로 쓴 게 아니라 기존 스펙을 재사용한 것 — 원본이 바뀌면 이 문서도 갱신해야 한다.
> 범위: 표준 14개 기능 + 00(정보구조) + 3D flyover(초안, 미확정). **총 97개 시나리오.**
> 상태 표기: ✅ 실제 동작으로 검증됨(브라우저로 직접 조작·확인) · ❌ 실제 동작이 스펙과 다름을 확인함 · 📝 테스트 코드는 있으나 미검증(로컬 DB 필요) · ⬜ 아직 확인 안 함.
> 2026-09-01 추가 확인: 로컬 dev 서버(mock 모드, DB 없이 `lib/mock.ts` 데이터)를 실제로 띄워서 Browser로 조작해 확인한 항목들을 ✅/❌로 반영했다. mock 모드라 로그인·저장·체크인 등 **쓰기가 실제로 영속되진 않지만**, 화면 전환·게이트·토글 같은 UI 동작은 진짜로 조작해서 관찰했다.

**⚠️ 확인된 스펙 간 모순(실측 완료)**: 00-information-architecture는 "탐색 탭 기본 표시 = 사진 피드"(§4·G/W/T)라고 명시하는데, 03-explore-map-feed는 "탐색 탭 기본 표시 = 지도"(구성요소·G/W/T)라고 명시한다. **로컬 서버를 띄워 `/explore/tokyo`에 직접 들어가 확인한 결과, 실제 동작은 03과 일치한다 — 첫 로드 시 지도가 뜨고 상단에 "피드" 토글이 있다.** 즉 00번 문서의 해당 문장이 실제와 다르다 — 00을 03에 맞춰 고쳐야 한다(코드를 바꿀 문제가 아니라 문서를 바로잡을 문제).

**⚠️ 새로 발견(실측): 체크인의 "소프트 게이트"가 스펙과 다르게 동작한다.** 저장(save) 액션은 스펙대로 오버레이 모달("컬렉션에 저장", 로그인 필요 안내 문구 + 닫기 버튼)로 뜬다 — 이건 정확히 맞다(01-1 참조). 하지만 GPS 체크인은 GUEST가 시도하면 모달이 아니라 **페이지 전체가 "로그인하고 인증하기" 버튼으로 바뀌고**, 그 버튼을 눌러 `/login`으로 이동하면 **원래 하려던 체크인으로 돌아오는 콜백 파라미터가 없다**(URL에 아무 정보도 안 실림). 로그인 완료 후에도 항상 `/city`로만 이동하는 코드(`app/login/page.tsx`)와 일치하는 동작이다. 즉 "로그인 성공 후 원래 액션이 이어진다"는 01번 스펙의 핵심 약속이 **체크인 경로에서는 실제로 안 지켜진다.**
