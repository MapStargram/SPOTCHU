# 지표 · 분석 이벤트 — 규칙 (rules)

## 불변식 (Invariants)
- **NSM = 방문 인증 완료 수**(prd §31). NSM은 **최초 방문 인증(unique)만** 계상하며, 재방문·중복 인증(prd §17 unique·24h 쿨다운)은 제외한다.
- 핵심 퍼널 단계는 **스팟 상세 조회 → 저장 → 컬렉션 생성 → 방문 인증 → 업로드**로 고정(prd §31).
- 이벤트명은 **snake_case** 고정, 속성 스키마는 이 문서의 표를 단일 기준으로 한다.
- prd에서 도출 가능한 이벤트만 계측한다(발명 금지).

## 집계 방식 (결정: 파생 카운트)
- MVP 내부 대시보드는 **파생 카운트**로 집계한다 — 별도 이벤트 로그 테이블을 두지 않고 도메인 테이블에서 직접 집계한다. (prd §35에 이벤트 엔티티 없음 → 발명 금지·단일 원천 규칙 준수.)
- **NSM = `CheckIn` 행 수**. `CheckIn`은 `@@unique([userId, spotId])`라 최초 1회만 존재하고 재방문은 update만 하므로(신규 행 없음), 행 수가 곧 최초 unique 인증 수다.
- **퍼널**(파생) = 각 단계 행동을 1회 이상 한 distinct 사용자 수. 저장=`CollectionItem` 소유자, 컬렉션 생성=비기본·비공식 `Collection` 소유자, 인증=`CheckIn` 사용자, 업로드=`Post` 작성자. 분모는 저장 단계.
- **커버리지**(파생) = `Spot`의 도시별 수 / `verificationStatus` 분포(검증=OFFICIAL+USER_VERIFIED).
- **발견·조회(퍼널 1단계)는 DB에 남지 않아 파생 불가** → 조회→저장 전환율은 외부 이벤트 파이프라인 도입 후 산출한다(아래 TODO). 파생 카운트는 사용자별 시퀀스가 아니므로 단계별 근사치로 취급한다.
- 구현: 순수 로직 [`lib/metrics.ts`](../../../lib/metrics.ts) · DB 집계 `getMetricsOverview()`([`lib/data.ts`](../../../lib/data.ts)) · 대시보드 `app/admin/metrics`.

## Do / Don't
- ✅ 모든 이벤트에 공통 속성(`anonymous_id`/`session_id`/`city`/`role`/`ts`)을 붙이고, 로그인 시 익명 식별자를 사용자와 병합한다.
- ✅ `checkin_success`에 `is_unique`를 실어 NSM 이중 계상을 막는다.
- ✅ 커버리지·리텐션은 이벤트가 아닌 서버 데이터 집계로 산출한다.
- ❌ 원시 GPS 좌표·정확 위치·EXIF·PII를 이벤트 payload나 URL 쿼리스트링에 넣지 않는다(prd §23).
- ❌ 구체 KPI 목표 수치를 임의로 확정하지 않는다(prd §32, 베타 후 확정).
- ❌ 스키마에 없는 이벤트·속성을 임의 추가하지 않는다(추가는 표 개정으로).

## 데이터·권한 규칙
- 지표·원시 이벤트 접근은 운영자·PM로 제한(최소 권한).
- 서버 사건 기반 이벤트(승격·검수 등)는 서버에서 방출하고 클라이언트 임의 생성 금지.
- 익명 사용자 이벤트는 `anonymous_id`로만 식별하며 개인 식별 정보와 결합하지 않는다.
