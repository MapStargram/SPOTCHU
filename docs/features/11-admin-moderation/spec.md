# 웹 어드민 · 검수 큐 · 신고 — 기능 스펙 (spec)

> 상위 원천: [`../../../prd.md`](../../../prd.md) · 규칙: [`./rules.md`](./rules.md) · 용어: [`../../glossary.md`](../../glossary.md)

## 목적
운영자(MODERATOR/ADMIN)가 사용자 생성 콘텐츠를 검수·조정하고 마스터 데이터를 관리하는 **별도 웹 어드민**을 정의한다. 신규 제보·신고·공식 승격 후보·작품 스틸 요청을 **하나의 통합 검수 큐**(`ModerationQueue`)에서 처리한다. (PRD §21·§22·§18)

## 진입점 / 사용자
- **형태**: 앱과 분리된 별도 웹 어드민. 모바일 하단 내비 탭에 노출하지 않는다.
- **권한**: `MODERATOR` / `ADMIN` 만 접근. `GUEST`/`USER`/`TRUSTED_USER` 접근 불가.
- **진입**: 어드민 URL 직접 접근 → 서버측 세션 권한 검사.
- **통합 검수 큐 유입원 (ModerationItem 4종)**:
  | 유입원 | 대상 | 출처 |
  |---|---|---|
  | 신규 제보 스팟 | `Spot`(`USER_REPORTED`) | [`../10-spot-registration/`](../10-spot-registration/) |
  | 신고된 스팟·사진 | `Spot` / `Post`(사진) | 신고 버튼(§22) |
  | 공식 승격 후보(인기) | `Spot`(`USER_VERIFIED`/인기 상위) | §18 |
  | 작품 스틸 등록 요청 | `Work` 관련 요청 | §21 |
- 사용자 관리·마스터 데이터 관리는 검수 큐와 별개의 어드민 섹션.

## 화면 상태
| 화면 | 상태 |
|---|---|
| 통합 검수 큐 목록 | 기본(유입원·상태·도시 필터, 정렬) / 빈 큐 / 로딩 / 에러 |
| 큐 아이템 상세 | 유입원별 검수 뷰(제보 스팟 / 신고 / 공식 승격 후보 / 작품 스틸) |
| 사용자 관리 | 목록(검색) / 사용자 상세(경고·정지·플래그 이력) |
| 마스터 데이터 | 도시·작품(회차)·배지 목록 및 편집 폼 |
| 권한 없음 | 비운영자 접근 시 거부(403) |

## 구성 요소
- **통합 검수 큐 (`ModerationQueue`)**: `ModerationItem` 리스트. 각 아이템은 유입원 4종 중 하나(코드 enum 값은 TODO).
- **스팟 검수 액션 바**: 승인 · 반려 · 정보 수정 · 검증 상태 변경(`verificationStatus`) · 중복 스팟 병합.
- **신고 처리 액션**: 숨김 · 삭제 · 무효(기각).
- **신고 사유 라벨**: 부정확한 위치 · 저작권 · 사유지 침해·민폐 · 부적절.
- **사용자 관리 패널**: 조회 · 경고 · 정지(밴) · 신뢰 사용자 플래그(`TRUSTED_USER`) 토글.
- **마스터 데이터 CRUD 폼**: `City` · `Work`(회차 `episode`) · `Badge` 정의.

## 인터랙션 흐름
1. **제보 스팟 검수**: 큐에서 `USER_REPORTED` 스팟 열람 → 승인 / 반려 / 정보 수정 / 검증 상태 변경 / 중복 병합 → 처리 결과를 제보자에게 인앱 알림(승인·반려, [`../13-notifications/`](../13-notifications/)).
   - 참고: `USER_REPORTED` → `USER_VERIFIED` 승격은 **서로 다른 3명 이상 GPS 인증 시 자동**이며 운영자 개입이 아니다(§18, glossary).
2. **신고 워크플로**: 사용자 신고(스팟·게시물) → `Report` 생성 → 큐 등록 → 운영자 검토 → 숨김 / 삭제 / 무효. 반복 신고 임계 초과 시 **자동 임시 숨김** 후 큐 우선 노출 → 운영자 최종 판단(임계값 TODO, §22).
3. **공식 승격**: 인기 스팟(좋아요·인증 상위)이 후보로 큐에 노출 → 운영자 검토 → `OFFICIAL` 승격 또는 보류. **자동 공식화 아님**(§18, 위치 정확성 원칙 보호).
4. **중복 스팟 병합**: 두 스팟 선택 → 유지/흡수 대상 지정 → 병합(연결 데이터 이관). 참조 이관 규칙은 TODO.
5. **사용자 관리**: 사용자 조회 → 경고 / 정지 / `TRUSTED_USER` 플래그 설정.
6. **마스터 데이터**: `City` · `Work`(회차) · `Badge` 생성·수정·삭제.

## 엣지 케이스
- 비운영자(`USER`/`GUEST`)의 어드민 접근 → 거부(403).
- 이미 처리된 아이템의 재처리 / 두 운영자의 동시 편집 충돌.
- 삭제된 스팟에 연결된 게시물 처리(§38).
- 병합 대상이 이미 병합·삭제된 경우.
- 신고 사유 누락 / 동일 사용자의 중복 신고.
- 작품 스틸 요청이 저작권상 직접 호스팅 불가(§24) → 반려 또는 외부 공식 출처 링크 안내.
- 정지(밴)된 사용자의 기존 콘텐츠 노출 처리.

## 인수 조건 (Given/When/Then)
- **Given** `USER` 권한 세션, **When** 어드민 URL에 접근, **Then** 접근이 거부된다(403).
- **Given** `MODERATOR`, **When** 큐에서 제보 스팟을 승인, **Then** 스팟 상태가 반영되고 제보자에게 승인 인앱 알림이 전송된다.
- **Given** 게시물 신고가 누적되어 임계를 초과, **When** 임계 도달, **Then** 해당 게시물이 자동 임시 숨김되고 큐에 우선 노출되어 운영자 최종 판단을 기다린다.
- **Given** 중복으로 판단된 두 스팟, **When** 운영자가 병합을 실행, **Then** 하나의 스팟으로 통합되고 연결 참조가 이관된다(구체 이관 규칙 TODO).
- **Given** `ADMIN`, **When** 도시·작품(회차)·배지를 생성, **Then** 마스터 데이터에 반영되어 앱에서 사용된다.
