# 알림 — 기능 스펙 (spec)

> 상위 원천: [`../../../prd.md`](../../../prd.md) · 규칙: [`./rules.md`](./rules.md) · 용어: [`../../glossary.md`](../../glossary.md)

## 목적
MVP의 **인앱 알림 최소 세트**를 정의한다. 알림 유형은 prd §20이 정한 정확히 3종 — (1) 배지 획득, (2) 제보 검수 결과(승인/반려), (3) 내 스팟이 `USER_VERIFIED`로 승격 — 뿐이다. 웹푸시·이메일은 후속(prd §20·§28, MVP 제외). 사용자에게 알림 센터(리스트)와 미읽음 **배지 카운트(badge count)** 를 제공한다.

## 진입점 / 사용자
- **수신자**: `USER`(로그인 사용자) 본인. 알림은 항상 **해당 사건의 당사자 본인에게만** 발행된다(배지를 얻은 사람, 제보한 사람, 자신이 제보한 스팟이 승격된 사람).
- **알림 센터 진입점 위치**: prd/IA(§9, [`../00-information-architecture/`](../00-information-architecture/))가 알림 탭·아이콘 위치를 정의하지 않음 → **TODO**(후보: 프로필 탭 상단 또는 전역 헤더의 알림 아이콘. rules 참조).
- **GUEST**: 알림 없음. 알림 센터 진입 시 소프트 게이트로 로그인 유도([`../01-auth-onboarding/`](../01-auth-onboarding/)).

## 화면 상태
1. **알림 센터(리스트)**: 발행 시각 역순 목록. 각 항목은 유형 아이콘 + 문구 + 시각 + 읽음/미읽음 구분.
2. **빈 상태**: 알림이 없을 때 안내 문구.
3. **미읽음 배지 카운트**: 알림 진입점 아이콘 위 미읽음 개수 배지. 0이면 미표시.
4. **로딩/에러 상태**: 목록 로드 실패 시 재시도 안내.

## 구성 요소
- **알림 진입 아이콘 + 미읽음 카운트 배지**: 미읽음 알림 수를 표시.
- **알림 리스트 항목**: 유형, 아이콘, 텍스트, 발행 시각, 읽음 상태, 딥링크 타깃.
- **알림 유형(MVP 3종)**:

| 유형 코드 | 트리거 | 수신자 | 딥링크 타깃 |
|---|---|---|---|
| `BADGE_EARNED` | `UserBadge` 부여(배지 획득 조건 충족) | 배지 획득자 | 프로필 배지([`../08-gamification-badges/`](../08-gamification-badges/)) |
| `REPORT_REVIEWED` | 운영자가 내 제보를 승인/반려 처리([`../11-admin-moderation/`](../11-admin-moderation/)) | 제보자 | 해당 스팟 상세([`../04-spot-detail/`](../04-spot-detail/)) |
| `SPOT_PROMOTED` | 내가 제보한 스팟이 `USER_REPORTED`→`USER_VERIFIED` 승격 | 제보자 | 해당 스팟 상세 |

- **읽음 처리 컨트롤**: 항목 열람 시 읽음 전환(일괄 읽음 처리 여부는 TODO).

## 인터랙션 흐름
```
사건 발생
  ├─ 배지 획득(UserBadge 부여)                    → BADGE_EARNED 알림 생성
  ├─ 운영자 제보 승인/반려(ModerationItem 처리)    → REPORT_REVIEWED 알림 생성
  └─ 스팟 USER_REPORTED→USER_VERIFIED 승격         → SPOT_PROMOTED 알림 생성
      → 서버가 수신자(본인)에게 인앱 알림을 미읽음으로 생성
      → 미읽음 배지 카운트 +1
      → 사용자가 알림 센터 열람 → 목록 표시
      → 항목 탭 → 딥링크 이동 → 해당 항목 읽음 처리 → 미읽음 카운트 -1
```

## 엣지 케이스
- **비로그인(GUEST)**: 알림 없음, 진입 시 로그인 유도. 알림은 로그인 사용자에게만 존재.
- **제보 반려 알림의 사유 노출**: 반려 사유 문구 노출 범위는 검수([`../11-admin-moderation/`](../11-admin-moderation/)) 결정에 종속 → **TODO**.
- **동시 다발 사건**: 배지 획득과 스팟 승격이 함께 일어나면 **각각 개별 알림**으로 발행(합치지 않음).
- **승격 중복 방지**: 스팟이 이미 `USER_VERIFIED`(또는 상위)면 이후 인증이 쌓여도 `SPOT_PROMOTED` 재발행하지 않는다(승격 전이 1회에만, glossary 승격 규칙).
- **재방문/중복 인증**: 방문 인증 중복(prd §17 unique·쿨다운)은 승격·알림을 추가로 발생시키지 않는다.
- **딥링크 대상 소멸**: 알림이 가리키는 스팟/배지가 이후 삭제·병합되면 딥링크를 안전하게 처리(안내 또는 비활성). 신고로 임시 숨김된 스팟(prd §22)의 알림 처리 방식은 TODO.
- **대량 알림**: 목록 페이지네이션/보관 기간은 TODO.
- **웹푸시·이메일**: MVP에서 발송하지 않음(후속).

## 인수 조건 (Given/When/Then)
- **Given** 내가 제보한 스팟이 서로 다른 3명의 GPS 방문 인증으로 `USER_VERIFIED`로 승격, **When** 승격이 발생, **Then** 제보자 본인에게 `SPOT_PROMOTED` 인앱 알림 1건이 생성되고 미읽음 카운트가 1 증가한다.
- **Given** 운영자가 내 제보를 승인 또는 반려 처리, **When** 처리가 완료, **Then** 해당 결과의 `REPORT_REVIEWED` 인앱 알림이 나에게 생성된다.
- **Given** 배지 획득 조건 충족으로 `UserBadge`가 부여, **When** 부여가 완료, **Then** `BADGE_EARNED` 알림이 생성되고 항목 탭 시 프로필 배지로 이동한다.
- **Given** 미읽음 알림이 존재, **When** 알림 센터에서 해당 항목을 열람, **Then** 항목이 읽음 처리되고 미읽음 배지 카운트가 감소한다.
- **Given** GUEST 사용자, **When** 알림 센터 진입을 시도, **Then** 표시할 알림이 없으며 로그인으로 유도된다.
