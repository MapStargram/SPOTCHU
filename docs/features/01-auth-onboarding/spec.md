# 로그인 · 온보딩 · 소프트 게이트 — 기능 스펙 (spec)

> 상위 원천: [`../../../prd.md`](../../../prd.md) · 규칙: [`./rules.md`](./rules.md) · 용어: [`../../glossary.md`](../../glossary.md)

## 목적
비로그인 사용자의 자유로운 열람을 보장하면서, 쓰기 액션을 시도하는 **순간에만** 로그인을 요구하는 소프트 게이트를 정의한다. 로그인 수단은 소셜(카카오·네이버·구글·애플)과 **이메일/비밀번호**를 함께 지원하며(소셜을 쓰지 않는 사용자 대응), 가입 시 필수 동의(이용약관·개인정보·위치기반서비스)와 만 14세 미만 제한을 포함한다. 이메일/비밀번호 가입은 이메일 인증과 비밀번호 재설정을 갖추고, 같은 사람의 여러 로그인 수단은 한 계정으로 연결·관리한다. 온보딩은 최소로 유지한다(권한 안내 최소).

## 진입점 / 사용자 (권한 포함)
- **소프트 게이트 진입**: GUEST가 쓰기 액션(저장·컬렉션 생성/편집·방문 인증·업로드·좋아요·제보)을 시도하는 순간. 액션 발생 지점(스팟 상세·카드·피드·+버튼 등)에서 모달/바텀시트로 뜬다.
- **명시적 로그인 진입**: 프로필 탭 등에서 사용자가 직접 로그인을 선택.
- **역할** (prd §36):
  - `GUEST`(비로그인): 열람만.
  - `USER`: 저장·컬렉션·인증·업로드·좋아요·제보.
  - `TRUSTED_USER`: 제보 즉시 노출 신뢰도 가산(운영 플래그).
  - `MODERATOR`/`ADMIN`: 어드민·검수·마스터데이터(범위 밖 — [`../11-admin-moderation/`](../11-admin-moderation/)).
- 신규 사용자는 가입(소셜 로그인 + 필수 동의) 완료 시 `USER` 역할을 부여받는다.

## 화면 상태
1. **로그인 화면**: 소셜 버튼(카카오·네이버·구글·애플) + **이메일/비밀번호 폼**(이메일·비밀번호 입력, 로그인 버튼, "비밀번호 찾기" 링크, "이메일로 가입" 링크). 소프트 게이트 시트/모달 형태 또는 프로필 진입의 전체 화면 형태. 닫기(나중에) 가능 — 닫으면 열람으로 복귀.
2. **이메일 가입 화면**: 이메일·비밀번호(+확인) 입력. 이어서 동의 화면. 가입 완료 시 이메일 인증 안내.
3. **동의 화면**: 신규 가입 시 1회 노출(소셜·이메일 공통). 필수 동의 항목(이용약관·개인정보·위치기반서비스)과 만 14세 이상 확인. 필수 동의 미완료 시 다음 진행 불가.
4. **이메일 인증 화면**: 메일의 링크 진입 시 토큰 검증 → 인증 완료/만료·오류 안내. 미인증 상태 로그인 시 재발송 안내 배너.
5. **비밀번호 재설정**: (a) 재설정 요청 화면(이메일 입력 → 계정 존재와 무관하게 동일 안내), (b) 메일 링크 진입 후 새 비밀번호 설정 화면(토큰 검증).
6. **계정 관리 화면(연결)**: 로그인한 사용자의 연결된 로그인 수단 목록(비밀번호 설정 여부 + 소셜 provider별 연결 상태). 각 소셜 **연결하기/해제**. 마지막 로그인 수단은 해제 불가.
7. **소프트 게이트 모달/바텀시트**: 쓰기 액션 시도 시 뜨는 로그인 유도 UI. 왜 로그인이 필요한지 짧게 안내 + 로그인 수단 + 닫기.
8. **에러/취소 상태**: OAuth/이메일 로그인 취소·실패 시 로그인 화면 유지 + 재시도 안내.

## 구성 요소
- 소셜 로그인 버튼 4종(`kakao` / `naver` / `google` / `apple`) — Auth.js provider 연동(prd §33).
- 이메일/비밀번호 폼: 이메일·비밀번호 입력, 가입 시 비밀번호 확인. 비밀번호 정책(최소 8자 등)은 서버 zod로 검증.
- 이메일 인증·비밀번호 재설정 토큰(`VerificationToken` 재사용, 만료 있음) + Resend 발송.
- 필수 동의 체크: `agreeTerms`(이용약관), `agreePrivacy`(개인정보), `agreeLocation`(위치기반서비스) + 만 14세 이상 확인.
- 계정 관리: 연결된 provider 목록·연결하기·해제(마지막 수단 보호).
- 게이트 컨텍스트: 로그인 성공 후 이어서 수행할 원래 액션 정보(어떤 스팟/게시물에 대한 어떤 액션인지).
- 닫기/나중에 컨트롤(열람 복귀).

## 인터랙션 흐름
```
GUEST 열람 → 쓰기 액션 탭 → 소프트 게이트 시트
  → provider 선택 → OAuth 인증
      → (신규) 동의 화면 → 필수 동의 + 만14세 확인 → 계정 생성(USER) → 원래 액션 이어서 수행
      → (기존) 즉시 원래 액션 이어서 수행
  → 취소/실패 → 시트 유지, 재시도 안내(닫으면 열람 복귀)
```
- 명시적 로그인(프로필)도 동일 OAuth·동의 경로를 따르되, 이어서 수행할 액션 컨텍스트 없이 로그인만 완료한다.

## 엣지 케이스
- **OAuth 취소/실패**: 로그인 화면/시트 유지, 열람은 계속 가능. 계정 생성·부작용 없음.
- **필수 동의 거부**: 계정 생성 안 됨. 소프트 게이트 유지, 열람은 계속 가능.
- **만 14세 미만 표시**: 가입 차단 + 안내 문구.
- **위치기반서비스 동의(법적)와 브라우저 위치 권한(기술)은 별개**: 가입 시 동의를 받아도 실시간 위치 권한은 방문 인증 시점에 별도 요청(prd §23, [`../07-gps-checkin/`](../07-gps-checkin/)).
- **세션 만료**: 재로그인 후 액션 재시도.
- **네트워크 실패(OAuth 중)**: 부분 상태 없이 실패 처리, 재시도 안내.
- **게스트 열람은 어떤 경우에도 차단하지 않는다**(홈·탐색·스팟/작품 상세·공개 컬렉션).
- **이메일 인증/재설정 토큰 만료·재사용**: 만료·사용된 토큰은 거부하고 재발송 안내. 토큰은 1회용.
- **이미 가입된 이메일로 재가입**: 계정 존재를 직접 노출하지 않고 처리(로그인/재설정 유도).
- **비밀번호 로그인 실패**: 이메일/비밀번호 불일치는 어느 쪽이 틀렸는지 구분하지 않는 동일 메시지.
- **마지막 로그인 수단 해제 시도**: 거부(잠금 방지).

## 인수 조건 (Given/When/Then)
- **Given** GUEST가 스팟 상세를 열람, **When** 저장 버튼을 탭, **Then** 소프트 게이트 시트가 뜨고 열람 화면은 유지되며 닫으면 그대로 열람을 이어간다.
- **Given** 신규 사용자가 소셜 로그인에 성공, **When** 동의 화면에서 필수 동의(이용약관·개인정보·위치기반서비스)를 완료하지 않음, **Then** 계정이 생성되지 않는다.
- **Given** 신규 사용자가 만 14세 미만임을 표시, **When** 동의를 진행, **Then** 가입이 차단되고 안내가 표시된다.
- **Given** 기존 사용자가 소셜 로그인, **When** OAuth 콜백이 성공, **Then** 동의 화면 없이 원래 시도한 액션이 이어진다.
- **Given** 비로그인 사용자, **When** 홈·탐색·스팟 상세를 열람, **Then** 로그인 없이 접근 가능하다.
- **Given** 이메일/비밀번호로 가입, **When** 필수 동의 완료 후 제출, **Then** 계정이 생성되고(비밀번호는 해시 저장) 인증 메일이 발송되며, 비밀번호 평문은 저장·응답 어디에도 없다.
- **Given** 이미 가입된 이메일, **When** 같은 이메일로 다시 가입 시도, **Then** 계정 존재를 직접 노출하지 않는 안내로 처리한다(중복 생성 안 됨).
- **Given** 비밀번호를 잊은 사용자, **When** 재설정을 요청, **Then** 이메일 존재 여부와 무관하게 동일한 "메일을 확인하세요" 안내가 나오고, 유효 토큰 링크로만 새 비밀번호를 설정할 수 있다.
- **Given** 이메일/비밀번호 계정으로 로그인한 사용자, **When** 계정 화면에서 소셜을 연결, **Then** 같은 `User`에 해당 provider가 추가되고 이후 그 소셜로도 같은 계정에 로그인된다.
- **Given** 로그인 수단이 하나뿐인 사용자, **When** 그 수단의 해제를 시도, **Then** 잠금 방지를 위해 해제가 거부된다.

## 관련 API / 데이터
- `User`(role: `GUEST`/`USER`/`TRUSTED_USER`/`MODERATOR`/`ADMIN`) + `passwordHash?`(bcrypt) — prd §35, §36.
- Auth.js provider: `kakao` / `naver` / `google` / `apple` + Credentials(이메일/비밀번호)(prd §33·§34). 세션 전략 `jwt`.
- 이메일 인증·비밀번호 재설정: `VerificationToken`(재사용) + Resend 발송.
- 서버액션: 가입(`signupWithEmail`), 이메일 인증(`verifyEmail`), 재설정 요청/확정(`requestPasswordReset`/`resetPassword`), 소셜 연결 해제(`disconnectProvider`). 모든 입력 zod 검증.
- 동의 이력(약관·개인정보·위치기반 동의 시각·버전) 저장 필드 — 필드 정의: [`../../data-model.md`](../../data-model.md).
- 인증·권한 시그니처: [`../../api-surface.md`](../../api-surface.md).

## Phase
0 (기반: 인증·세션·역할·소프트 게이트 셸). 각 쓰기 액션의 게이트 연동은 해당 기능 Phase(저장/컬렉션 2, 인증/배지 3, 업로드/좋아요/제보 4)에서 완성.
