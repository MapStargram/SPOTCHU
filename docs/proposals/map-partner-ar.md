# 제안 초안 — 브랜드 지도·파트너 수익화·AR 준비

> **상태: 반영됨 (2026-08-28).** PRD §12(지도)·§28(로드맵)·§41(미결정)·§42(신설) + [`data-model.md`](../data-model.md)(Partner 엔티티·enum)에 반영. 결정: 파트너=별도 엔티티, 지도 최소 컨텍스트 유지. 이 문서는 배경·이력용. 남은 것: `features/15-partner-monetization` spec 신설(포스트-MVP).
> 상위 원천: [`prd.md`](../../prd.md). 관련 기존 섹션: §5(목표/비목표)·§12(지도)·§13(스팟)·§28(후속 로드맵)·§31(지표)·§41(미결정).
> 배경: 커스텀 브랜드 지도 + 가맹점 스폰서 노출 수익화 + AR 글라스 대비를 하나의 방향으로 정리.

## 0. 정합성 원칙 (제일 중요)
- **MVP 범위는 그대로.** §5 비목표의 "수익화 기능"·"네이티브 앱"은 **유지**한다. 아래 B(수익화)·C(AR)는 **포스트-MVP**다.
- MVP에서 **지금 채택하는 건 UX·데이터 준비뿐**: A(브랜드 지도·길찾기·썸네일 마커)와, B·C가 나중에 붙을 수 있게 하는 **데이터 모델 훅**. 실제 광고 판매·AR 기능은 트래픽(§31 NSM) 확보 후.
- 불변식 재확인: 지도 좌표는 **촬영자 위치**(§12). 파트너/광고가 이 정확성과 검증 기반 신뢰를 **훼손하지 않는다**.

## A. 지도 표현 · 길찾기 (§12 개정 — MVP 채택 가능)

### A-1. 브랜드 커스텀 지도 + POI 표시 규칙
- 기본 Google 지도 대신 **브랜드 커스텀 스타일** 적용. 지도는 **큐레이션된 핀만** 보이는 깨끗한 캔버스로.
- **지도에 표시**: ① 사진 스팟(스팟/랜드마크) ② 관광명소·애니 성지 ③ 파트너(가맹점, 포스트-MVP) — 이 3종만.
- **기본 POI는 숨김**(`poi` visibility off). 단 **최소 컨텍스트**(주요 교통·대형 랜드마크)는 남길지 미결정(길찾기 UX상 완전 제거는 위험).
- 기술 제약(구현 메모): 커스텀 스타일은 **클라우드 기반 Map ID**로 관리하고 마커는 **AdvancedMarkerElement**를 쓴다. (인라인 `styles` JSON은 썸네일 마커와 병행 불가 — Snazzy 등 JSON 테마는 Map ID로 import.) *API 최신 상태는 구현 시 확인.*

### A-2. 마커 썸네일
- 마커에 스팟 **대표 사진(`coverImageUrl`) 썸네일** 노출. 줌인·뷰포트 기준으로만 로드(§30 비용/성능).
- 클러스터링과 병행(03 탐색 지도 세션에 이미 반영됨).

### A-3. 길찾기 = 딥링크 (라우팅 직접 구현 안 함)
- 인앱 라우팅 미구현. **현재 위치 → 스팟**을 Google Maps로 딥링크: `https://www.google.com/maps/dir/?api=1&origin=<현재>&destination=<shooterLat,Lng>&travelmode=walking`.
- 인앱에는 **직선거리(haversine, 기존 `lib/geo`)만** 표시 후 딥링크. 좌표는 우리가 소유, 라우팅은 위임 → 정확성 불변식 유지.
- §28 로드맵 2번(동선/경로)의 경량 선행 구현으로 위치.

## B. 파트너 · 수익화 모델 (신설 §42 제안 — 포스트-MVP, 데이터만 지금 준비)

### B-1. 개념
- **가맹점/파트너(Partner)**가 **지도 노출 + 목록 상위 노출**의 대가로 비용을 지불하는 스폰서 모델.
- §28 로드맵 5번(수익화: 제휴 커머스→구독)의 **로컬 파트너 광고형 변주**로 추가.

### B-2. 신뢰 가드레일 (필수 — 안 지키면 §4 비전·§5 "SNS화 회피" 훼손)
1. **광고 명확 표시** — 스폰서/파트너 핀·카드는 "광고/파트너" 라벨 병기. **한국 표시·광고법(뒷광고 금지) 준수.** (법무 확인 필요)
2. **랭킹 분리** — 사진 스팟의 정확성·인증 기반 랭킹을 **돈으로 덮지 않는다**. 스폰서는 **별도 레인/슬롯**으로, 오가닉 결과와 시각적·구조적 분리.
3. **맥락 연결** — 파트너는 해당 **스팟/지역/작품과 관련**된 경우만(예: 성지 근처 테마 카페). 무맥락 광고 금지.
4. **타이밍** — 유저 0인 MVP엔 영업 이르다. 모델(엔티티·플래그)만 준비, **실제 판매는 NSM 트래픽 확보 후**.

### B-3. B2B 온보딩 (별도 플로우)
- 파트너가 **자기 위치를 지도에서 선택·등록**하는 B2B 화면(참고 UX: 업체 위치 등록형). 일반 사용자 제보(§18)와 **분리된 권한·검수** 대상.
- 미결정: 셀프서비스 vs 운영자 대행, 과금 방식(고정/기간/노출당), 검수 기준.

## C. AR 글라스 준비 (§28 로드맵 추가 — 지금은 "데이터 준비"만)

- **SPOTCHU는 이미 AR에 유리.** 핵심 불변식 `shooterLat/Lng` + `bearing`(방위각)이 AR 오버레이에 필요한 **정확 위치+방향**을 이미 보유(대부분 지도앱은 방위각 없음). = 잠재적 차별점.
- **준비 = AR 코드가 아니라 데이터 위생 + 통합 POI API.** 원칙:
  - 마커 = POI = (미래)AR 오버레이가 **같은 데이터원**(좌표·방위각·썸네일·카테고리)을 쓰도록 구조화.
  - 지도 전용 렌더링에 로직을 하드코딩하지 않기(표현과 데이터 분리).
- **YAGNI**: 실제 AR 렌더링/디바이스 연동은 포스트-MVP. 지금은 위 원칙 체크리스트만 유지.

## D. 데이터 모델 영향 (data-model.md 반영 예정 — 초안)

- **신설 `Partner`(가맹점)** — Spot과 **별도 엔티티** 권장(사진 스팟의 촬영자-위치 불변식·검증 모델을 오염시키지 않기 위해).
  - 초안 필드: `id, name, category, lat, lng, cityId, thumbnailUrl?, sponsorTier(enum), sponsoredUntil?(date), status(PENDING|ACTIVE|EXPIRED), ownerContact?, linkedSpotIds?/areaId?(맥락 연결), createdAt`.
  - **미결정**: Partner를 완전 별도 엔티티 vs `Spot`의 한 타입(`kind`)으로 둘지 — **권장은 별도 엔티티**.
- **`Spot`/공통 POI**: 지도·(미래)AR가 공유할 최소 필드 = 좌표·`bearing`·`coverImageUrl`·카테고리·표시타입. (대부분 이미 존재)
- **지도 표시 타입** enum 검토: `PHOTO_SPOT | LANDMARK | PILGRIMAGE | PARTNER` (표시/필터·광고 라벨 구분용).

## E. 미결정 사항 (§41에 추가 예정)
1. **POI 최소 컨텍스트** — 기본 POI 전면 숨김 vs 교통·대형 랜드마크 유지 범위.
2. **파트너 = 별도 엔티티 vs Spot 타입** — (권장: 별도) 최종 확정 필요.
3. **광고 표시·법무** — 표시광고법 준수 문구·형식, 검수 책임 범위. 법률 검토 필요.
4. **과금 모델** — 고정료/기간/노출·클릭당 중 선택, 파트너 티어 정의.
5. **스폰서 노출 상한** — 화면당 스폰서 비율(오가닉 대비) 상한으로 신뢰 보호.
6. **AR 착수 트리거** — 어떤 지표/디바이스 시점에 AR를 실제 개발로 승격할지.
