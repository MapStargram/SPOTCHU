# 스팟 리서치 → 데이터 반영

실제 스팟으로 SPOTCHU 데이터를 채운다. **법적 안전선**(PRD §24·§41)을 반드시 지킨다.

## 법적 안전선 (필수)
- 인스타·스레드·유튜브·틱톡의 **개인 게시물 스크래핑 금지**, 사진·영상·애니/영화 스틸 **복제·재호스팅 금지**.
- 수집 대상은 **텍스트 사실 메타데이터 + 출처 URL**뿐. 이미지는 서비스 자체(현재 그라디언트 플레이스홀더) 사용.
- 각 스팟에 **공개·신뢰 출처 URL 1개** 필수(관광청·위키·여행매체·성지순례 위키 등).

## 절차
1. **조사 범위 분할**: 도시(서울·도쿄) × 유형(사진 명소 / 애니 성지 / 영화·드라마)로 나눈다.
2. **병렬 리서치**: 각 범위에 `spot-researcher` 서브에이전트를 띄운다. 각 에이전트는 아래 스키마의 JSON 배열을 반환:
   ```json
   [{ "title","city","category","lat","lng","subject","area",
      "work"?,"scene"?,"tip","lens"?,"time"?,"sourceUrl" }]
   ```
3. **취합·중복 제거**: 좌표/작품/출처가 불확실한 항목은 버린다. 같은 스팟은 하나로.
4. **데이터 매핑** → `lib/mock.ts` 형식으로 변환:
   - `id`(슬러그) · `title` · `city` · `categoryLabel`(🏯 랜드마크 / ⛩️ 애니 성지 / 🎬 드라마 / ✨ 포토 스팟 / 🌸 계절) · `verified`("user"|"reported" 기본, 유명·검증된 곳은 "official")
   - `thumbGrad`/`heroGrad`(브랜드 팔레트 그라디언트) · `subtitle`(area + 추천 시간) · `angle`/`lens`/`tip` · `workId`(작품 연결) · `source`(sourceUrl)
   - 좌표는 `SPOT_COORDS`에 `{lat,lng}` 추가. 작품은 `WORKS`에 추가.
5. **반영·검증**: `lib/mock.ts`(+ 필요 시 `WORKS`) 갱신 → `npm run typecheck && npm run build` → 데모에서 확인.
6. (DB 사용 시) `npm run db:seed`로 실 DB에도 반영.

## 주의
- `Spot`에 `source?`(출처 URL) 필드를 두고 상세 화면에 "출처" 링크로 노출(저작권 투명성).
- 안전: 철도 선로 위 등 위험 위치 제외.
- 과장·추측 금지. 사실 확인된 스팟만.
