# SPOTCHU — 제품 요구사항 정의서 (PRD)

> **문서 성격**: 이 문서는 SPOTCHU MVP 개발의 **단일 원천(single source of truth)** 이다. 화면·기능의 상세 스펙은 [`docs/features/`](docs/features/) 로, 데이터/기술 상세는 [`docs/data-model.md`](docs/data-model.md)·[`docs/tech-stack.md`](docs/tech-stack.md)·[`docs/api-surface.md`](docs/api-surface.md) 로 분리한다. 용어는 [`docs/glossary.md`](docs/glossary.md) 를 따른다.
>
> **작업 명칭**: SPOTCHU (가칭, 변경 가능) · **작성일 기준**: 2026-08-27 · **상태**: MVP 기획 확정

---

## 1. 문서 개요
- **목적**: 지도 기반 사진 스팟 발견·여행 계획·현장 방문 인증 서비스의 MVP를 정의하고, 개발이 바로 착수 가능한 수준의 요구사항을 제공한다.
- **범위**: 반응형 웹 / PWA MVP. 출시 도시는 **서울 + 도쿄**. 초기 콘텐츠는 **애니 성지 + 일반 여행 사진 스팟** 중심.
- **독자**: 개발자(사람 및 에이전트), 디자이너, 운영자, 이해관계자.
- **문서 구조**: 본 PRD(개요·정책·범위) → `docs/features/*`(화면·기능 상세) → `docs/data-model.md`(엔티티) → `docs/api-surface.md`(API).

## 2. 제품 배경
애니메이션·영화·드라마·SNS 사진 속 **실제 장소를 같은 위치·구도로 촬영**하고 싶은 수요가 크다. 기존 지도/추천 앱은 "장소"는 알려주지만 "어디에 서서 어느 방향으로 찍어야 그 사진이 나오는지"를 알려주지 못한다. SPOTCHU는 이 공백을 메운다.

## 3. 문제 정의
1. **위치는 알아도 구도를 모른다** — 도쿄타워는 찾아도 "골목 사이로 보이는 그 각도"를 못 찾는다.
2. **정보가 흩어져 있다** — 성지·촬영지 정보가 블로그·SNS에 분산되어 좌표·접근법이 부정확하다.
3. **여행 준비-현장-기록이 단절** — 발견, 계획, 현장 내비게이션, 방문 기록이 각기 다른 앱에 흩어진다.
4. **신뢰도 판단이 어렵다** — 어떤 위치 정보가 검증된 것인지 알 수 없다.

## 4. 제품 비전
> 한국과 일본의 사진 명소·콘텐츠 촬영지·애니 성지를 **정확한 지도 위치와 촬영 구도**로 발견하고, 여행 계획부터 방문 인증까지 즐기는 지도 기반 여행 커뮤니티.

인스타그램의 사진 탐색 + 지도 서비스의 위치 정보 + 여행 컬렉션 + 도감/스탬프 투어의 수집 경험을 결합한다. 단, MVP는 인스타그램을 복제하지 않는다 — 피드는 **스팟을 발견하기 위한 수단**이다.

**핵심 루프**: 지도/피드에서 발견 → 스팟 상세 확인 → 컬렉션 저장 → 현장 방문 → GPS 인증 → (선택) 사진 업로드 → 방문 기록·배지 수집.

## 5. 목표와 비목표
### 목표 (MVP)
- 서울·도쿄에서 정확한 스팟을 발견하고 여행 계획(컬렉션)을 세우는 경험 제공.
- 현장에서 스팟을 찾아가 GPS로 방문 인증하고 수집(배지)으로 이어지는 경험 제공.
- 검증 상태로 신뢰도를 명확히 구분하는 스팟 데이터 체계 구축.
- 사용자 제보로 콘텐츠가 확장되는 구조 + 운영자 검수 체계.

### 비목표 (MVP에서 하지 않음)
- 인스타그램 수준의 SNS(팔로우·DM·해시태그 탐색 전면화).
- 댓글, 사용자 팔로우.
- 날짜별 상세 일정표, 교통편 자동 연결, 최적 동선 자동 추천.
- 네이티브 앱(iOS/Android) — 웹/PWA로 먼저 검증 후 확장.
- 구도 유사도 자동 채점(사진 비교 AI).
- 수익화 기능.

## 6. 타깃 사용자 및 페르소나
- **주 타깃**: 일본 여행을 준비하는 한국인 여행자(도쿄·오사카·후지산 등에서 사진 스팟을 찾는 사람).
- **보조 타깃**: 인스타용 사진을 찍는 일반 여행자.
- **특화 타깃**: 애니 성지순례 팬(강력하지만 전체를 이들 전용으로 제한하지 않음).

**페르소나 P1 — 지민(27, 여행 준비 중)**: 다음 달 도쿄 3박4일. "인스타에서 본 그 후지산 편의점 사진, 정확히 어디지?"를 해결하고 싶다. 여행 전에 스팟을 모아 동선을 잡는 게 1순위.

**페르소나 P2 — 현우(24, 성지순례 팬)**: 특정 애니의 배경지를 회차별로 순례하고 인증하고 싶다. 작품별 진행률·배지에 반응한다.

**페르소나 P3 — 서연(30, 현장 여행자)**: 이미 도쿄에 있고, "지금 내 주변에서 사진 잘 나오는 곳"을 찾아 바로 이동·촬영·인증한다.

## 7. 핵심 사용자 시나리오
1. **여행 전 발견·계획(P1)**: 홈에서 도쿄 선택 → 추천 컬렉션/피드 탐색 → 스팟 상세 확인 → "도쿄 3박4일" 컬렉션에 저장 → 순서 정리.
2. **성지순례(P2)**: 작품 상세에서 회차별 스팟 확인 → 컬렉션 저장 → 현장 방문·인증 → 작품 진행률·배지 획득.
3. **현장 촬영(P3)**: 탐색 탭 '내 주변' 필터 → 근처 스팟 상세 → 서는 위치·카메라 방향 확인 → 촬영 → GPS 인증 → 사진 업로드.
4. **제보 기여**: 새 스팟을 +버튼으로 등록 → `USER_REPORTED` 상태로 즉시 노출 → 3명 인증 시 `USER_VERIFIED` 승격.

전체 흐름 상세: [`docs/features/00-information-architecture/spec.md`](docs/features/00-information-architecture/spec.md).

## 11. 화면별 기능 요구사항

## 12. 지도 및 위치 기능 요구사항
- **지도 제공자**: Google Maps JS API.
- **핀 인코딩**: 색 = 검증 상태, 아이콘 = 카테고리, 숫자 = 클러스터.
- **핵심 원칙**: 지도 좌표는 **촬영자가 서는 위치**. 촬영 대상과 혼동 금지. 카메라 방향은 상세에서 화살표로 표시.
- **주변 검색**: 현재 위치 기준 반경 쿼리(PostGIS).
- **비용 관리**: 지도 로드/세션당 호출을 지표화, 정적 지도·타일 캐싱 폴백 검토. 상세: [`docs/features/03-explore-map-feed/spec.md`](docs/features/03-explore-map-feed/spec.md).

## 13. 스팟 데이터 구조
- **필수(MVP)**: 이름, 카테고리, 좌표(촬영자 위치), 도시/지역, 대표 사진, 촬영 대상(텍스트).
- **선택**: 카메라 방향(방위각), 접근 방법, 촬영 팁, 추천 시간대/계절, 추천 렌즈·줌, 난이도, 혼잡도, 주의사항, 관련 작품/회차, 원본 장면.
- **자동**: 주소(역지오코딩), 검증 상태, 인증·좋아요·저장 집계.
- 필드 정의: [`docs/data-model.md`](docs/data-model.md).

## 14. 작품 및 콘텐츠 데이터 구조
- `Work`(작품): 제목, 유형(애니/영화/드라마/…), 대표 이미지(운영자 관리), 설명.
- `Spot ↔ Work` 다대다 + 회차/장면 메모(`episode`, `sceneNote`).
- 작품 상세 = 해당 작품의 스팟 리스트 + 성지순례 진행률. 상세: [`docs/data-model.md`](docs/data-model.md).

## 15. 컬렉션 데이터 구조
- `Collection`: 소유자, 제목, 설명, 공개범위(`PRIVATE`/`LINK`), `isOfficial`(운영자 큐레이션 플래그), 커버.
- `CollectionItem`: 스팟 참조, `order`(정렬), `day`(nullable, 후속 날짜 일정 확장 여지).
- 스팟은 여러 컬렉션에 중복 저장 가능(다대다). 상세: [`docs/data-model.md`](docs/data-model.md).

## 16. 게시물과 좋아요 구조
- `Post`: 작성자, 연결 스팟(필수), 사진 1~5장, 캡션, `isVerifiedShot`(GPS 인증 사진 뱃지).
- `Like`: 게시물에만 부여. 스팟 인기도 = 저장수 + 인증수 + 연결 게시물 좋아요 합산 파생 지표.
- 댓글·팔로우는 후속. 상세: [`docs/features/09-community-feed-upload/spec.md`](docs/features/09-community-feed-upload/spec.md).

## 17. GPS 방문 인증 정책
- 스팟 허용 반경(기본 100m, 스팟별 오버라이드) 내 + GPS 정확도 `accuracy ≤ 50m` 일 때만 인증 허용.
- GPS만으로 방문 완료 가능. 사진 업로드는 선택.
- 스팟당 방문 완료는 **최초 1회만 unique 카운트**, 재방문은 기록되나 통계·배지 중복 없음. 재인증 쿨다운 24h.
- Mock location 감지 시 인증 보류. 서버 타임스탬프 기록.
- 반경 밖 → 남은 거리 안내·재시도 / 정확도 불량 → "실외로 이동 후 재시도".
- 상세: [`docs/features/07-gps-checkin/spec.md`](docs/features/07-gps-checkin/spec.md).

## 18. 스팟 등록과 검수 프로세스
- 사용자 제보 → 즉시 `USER_REPORTED` 상태로 지도 노출 → 운영자 사후 검수(승인/반려/수정/검증상태 변경/병합).
- `USER_REPORTED` → `USER_VERIFIED`: 서로 다른 사용자 3명 이상 GPS 인증 시 자동 승격.
- 인기 스팟(좋아요·인증 상위)은 공식 승격 우선 검수 큐로 노출(자동 공식화 아님).
- 상세: [`docs/features/10-spot-registration/spec.md`](docs/features/10-spot-registration/spec.md) · [`docs/features/11-admin-moderation/spec.md`](docs/features/11-admin-moderation/spec.md).

## 19. 검색, 필터 및 정렬
- **검색 대상**: 스팟명 · 작품명 · 촬영 대상/랜드마크 · 지역.
- **검색 범위**: 선택 도시 내 기본 + "전체에서 검색" 토글.
- **필터**: 카테고리 · 검증상태 · 작품 · 시간대(야경/일몰/일출) · '지금 내 주변'.
- **정렬**: 인기순(기본) · 거리순 · 최신순.
- 상세: [`docs/features/05-search-filter/spec.md`](docs/features/05-search-filter/spec.md).

## 20. 알림 정책
- MVP: **인앱 알림 최소만** — 배지 획득, 제보 검수 결과(승인/반려), 내 스팟이 `USER_VERIFIED` 승격.
- 웹푸시·이메일은 후속. 상세: [`docs/features/13-notifications/spec.md`](docs/features/13-notifications/spec.md).

## 21. 관리자 기능
- **별도 웹 어드민**(운영자 역할). 통합 검수 큐(제보·신고·공식 승격 후보·작품 스틸 요청).
- 스팟 검수 액션: 승인/반려/수정/검증상태 변경/중복 병합.
- 사용자 관리: 조회·경고·정지·신뢰 사용자 플래그.
- 마스터 데이터 CRUD: 도시·작품(회차)·배지 정의.
- 상세: [`docs/features/11-admin-moderation/spec.md`](docs/features/11-admin-moderation/spec.md).

## 22. 신고 및 콘텐츠 운영 정책
- 스팟·게시물에 신고 버튼 → 통합 검수 큐. 사유: 부정확한 위치 / 저작권 / 사유지 침해·민폐 / 부적절.
- 반복 신고 임계 초과 시 자동 임시 숨김 → 운영자 최종 판단.
- 상세: [`docs/features/11-admin-moderation/spec.md`](docs/features/11-admin-moderation/spec.md).

## 23. 개인정보 및 위치정보 고려사항
- 위치 권한 목적 고지, **방문 인증 시에만** 실시간 위치 사용.
- 인증 **결과만** 저장(원시 좌표 이력 미보관). 업로드 사진 EXIF 위치는 서버 저장 전 제거.
- 가입 시 이용약관 + 개인정보 + 위치기반서비스 동의(한국 위치정보법 대응), 만 14세 미만 제한.
- 상세: [`docs/features/12-policies-safety-copyright-privacy/spec.md`](docs/features/12-policies-safety-copyright-privacy/spec.md).

## 24. 저작권 및 작품 이미지 사용 고려사항
- 서비스는 **작품 원본 스틸을 직접 호스팅하지 않음**. 비교/설명은 사용자 실촬영·텍스트 중심, 원본은 외부 공식 출처 링크로 안내.
- before/after 슬라이더 소스 = **스팟 대표 사진(실촬영) ↔ 내가 찍은 사진**.
- 외부 지오태그 콘텐츠 시딩은 **좌표·출처 메타데이터만** 수집(이미지 재호스팅 금지), 권리자 요청 시 즉시 삭제(notice & takedown).
- 상세: [`docs/features/12-policies-safety-copyright-privacy/spec.md`](docs/features/12-policies-safety-copyright-privacy/spec.md).

## 25. 안전 및 사유지 관련 정책
- 등록 시 안전 태그(사유지/철도/차도/영업장) 체크 필수. 위험 스팟은 경고 배너·주의사항 필수.
- 철도 선로 등 고위험 유형은 등록 차단.
- 스팟에 촬영 매너 고지, 신고 사유에 사유지 침해·민폐 포함.
- 상세: [`docs/features/12-policies-safety-copyright-privacy/spec.md`](docs/features/12-policies-safety-copyright-privacy/spec.md).

## 26. MVP 범위
- 인증(카카오·구글·애플), 홈/도시, 탐색(지도⇄피드), 스팟 상세(+비교 슬라이더), 검색·필터, 컬렉션(저장·순서·지도), GPS 방문 인증, 게임화 기본(방문수·도시/작품 달성률·컬렉션 완주·배지 3종), 사진 업로드·도시 피드·좋아요, 스팟 제보, 웹 어드민(검수 큐·신고·마스터데이터), 인앱 알림 최소, 정책(저작권·안전·개인정보).
- 도시: **서울 + 도쿄**.

## 27. MVP 제외 범위
- 댓글, 팔로우, 웹푸시, 날짜별 일정표/자동 동선, 네이티브 앱, 구도 유사도 AI, 수익화, 다국어 콘텐츠 필드(번역 필드만 미리 마련), 정보수정 기여자·시즌 배지.

## 28. 후속 버전 로드맵
1. 커뮤니티 확장: 댓글·팔로우·팔로우 피드.
2. 여행 계획 고도화: 날짜별 일정(`day` 활용)·동선 추천·지도 경로.
3. 방문 인증 고도화: 구도 유사도 점수, 사진 자동 비교.
4. 알림: 웹푸시·이메일.
5. 수익화: 여행 제휴 커머스 → 프리미엄 구독.
6. 지역 확장: 오사카·교토·부산 등, 콘텐츠 카테고리 확장(MV·앨범 재킷·광고·예능).
7. 네이티브 앱(iOS/Android).

## 29. 비기능 요구사항
- 모바일 우선 반응형 + PWA(홈 추가, 오프라인 셸).
- 접근성 기본(WCAG AA 지향): 시맨틱 마크업, 키보드 포커스, 대비, 대체 텍스트.
- 국제화 대비: UI 문자열 i18n 구조(ko 우선, en 여지).
- 보안: 인증 세션, 서버측 권한 검사, 입력 검증, 신고/차단.
- 관측성: 분석 이벤트, 에러 로깅.

## 30. 성능 및 접근성 요구사항
- 첫 콘텐츠 표시(모바일 3G Fast 기준) LCP < 2.5s 지향, 지도 초기 로드 지연 로딩.
- 이미지: 썸네일·반응형·지연 로딩, WebP/AVIF.
- 지도 호출 최소화(뷰포트 기반 로드, 디바운스).
- 접근성: 색만으로 정보 전달 금지(검증상태는 색+아이콘/라벨 병기).

## 31. 분석 이벤트 및 핵심 지표

- **리텐션**: D1/D7/D30. **커버리지**: 도시별 스팟 수/검증 비율. **비용**: 지도 호출/세션.

## 32. 성공 기준
- MVP 초기엔 정성 목표 + 방향성 지표(인증 루프 완주율·재방문율 개선)로 운영, 구체 KPI 수치는 베타 데이터 확보 후 확정.

## 33. 권장 기술 스택
- **프론트**: Next.js(App Router) + TypeScript + Tailwind, PWA.

- **지리**: PostgreSQL + PostGIS.
- **스토리지**: Cloudflare R2. **호스팅**: Vercel. **지도**: Google Maps.
- 상세·근거: [`docs/tech-stack.md`](docs/tech-stack.md).

## 41. 미결정 사항 (Open Questions)
1. **외부 지오태그 시딩의 법적 적합성** — 각 플랫폼(Instagram/Threads/YouTube/블로그) 약관 및 저작권상 좌표·출처 메타데이터 수집 방식의 허용 범위. **법률 검토 필요**. 그전까지는 운영자 수동 확인 기반으로 제한 운영.
2. **구체 KPI 수치** — 베타 데이터 확보 후 확정(§32).
3. **소셜 로그인 우선순위 노출 순서**(카카오 우선 여부) 및 애플 로그인 웹 심사 요건 확인.
4. **지도 비용 상한**과 초과 시 폴백(정적 지도) 발동 임계.
5. **제품 정식 명칭** — SPOTCHU 확정 여부(현재 가칭).
6. **콘텐츠 다국어 시점** — 일본 현지 사용자 유입 시 ja 필드 도입 시점.
